  HOW IT WORKS — FULL PIPELINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PHASE A — SERVER STARTUP (runs once, automatically)
─────────────────────────────────────────────────────
1. Reads  backend/data/UC1_RAG_Pricing_Matrix_1.pdf
         (this is the POLICY file — pricing tiers, uptime rules, penalties)

2. Splits the policy text into chunks (~2000 chars each)

3. Converts each chunk into a 384-number vector using
   the all-MiniLM-L6-v2 embedding model

4. Stores all vectors + text in Qdrant (backend/qdrant_data/)
   under a collection called "conditions_base"

   Result: Qdrant now holds your policy knowledge, ready to search.

PHASE B — WHEN YOU UPLOAD A CONTRACT PDF
─────────────────────────────────────────────────────
Step 1 │ TEXT EXTRACTION
       │  pdfplumber reads every page of the uploaded PDF
       │  Tables are extracted separately as structured rows
       │  Output: plain text of the full contract

Step 2 │ RAG LOOKUP (Qdrant)
       │  Query: "pricing tiers penalties uptime SLA"
       │  → Query is embedded into a vector
       │  → Vector compared against all policy chunks in Qdrant
       │  → Top 4 most similar policy chunks returned
       │  Output: relevant policy context (tier fees, uptime rules, penalties)

Step 3 │ LLM EXTRACTION (Gemma 4 31B via Google AI)
       │  Prompt = Contract Text + Policy Context
       │  Gemma reads both and extracts:
       │   • contract_type, vendor, client, start_date
       │   • payment_window, billing_day, evaluation_period
       │   • monthly_fee (raw number from document)
       │   • bonus_percent, target_uptime_percent
       │  Output: JSON with extracted field values

Step 4 │ TIER OVERRIDE (programmatic — guaranteed accurate)
       │  Takes the extracted monthly_fee and finds closest policy tier:
       │   ₹35,000  → Standard ETL Pipelines       (99.0% uptime)
       │   ₹78,000  → Advanced Agentic Workflows    (99.5% uptime)
       │   ₹1,50,000→ Mission-Critical Architecture (99.9%, 15% penalty)
       │  Overrides: monthly_fee, service_tier,
       │             minimum_uptime_percent, penalty_percent
       │  Output: Final corrected JSON

Step 5 │ RESPONSE
       │  JSON sent to frontend → fields displayed in the UI

  NOTES & TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

• API docs (Swagger UI): http://127.0.0.1:8000/docs

• If you see "Address already in use":
    lsof -ti:8000 | xargs kill -9

• If you see "Qdrant already accessed by another instance":
    Only ONE uvicorn process can run at a time.
    Kill all old processes first, then restart.

• To change the model:
    export GEMINI_MODEL="gemma-4-31b-it"

• The qdrant_data/ folder is created automatically on first run.
  It persists between restarts — policy chunks stay indexed.

• Uploaded contract PDFs are deleted automatically after processing.

• To update the policy/pricing rules:
    Replace backend/data/UC1_RAG_Pricing_Matrix_1.pdf
    then restart the server — it will re-index automatically.
